# نتيجة اختبار التشغيل المتزامن — 23 أكتوبر 2026

## الحكم

اجتاز الباك إند اختبار قدرة لـ100 مستخدم نشط إجمالًا: 80 عميلًا و20 مندوبًا،
لمدة خمس دقائق قياس بعد رفع الحمل والإحماء. نُفذ الاختبار على نسخة معزولة
على سيرفر المستخدم، باستخدام صورة التطبيق نفسها المشغلة في الإنتاج.
هذه نتيجة إيجابية لهذا السيناريو والحجم والمدة، وليست اعتمادًا لسعة أكبر
أو لجميع ظروف الشبكة والإشعارات الخارجية.

## البيئة والعزل

- Hostinger KVM 4: أربعة vCPU و16 GB RAM و200 GB قرص، Ubuntu 24.04.
- إعداد الإنتاج الفعلي، وإعداد نسخة الاختبار: أربعة Gunicorn processes،
  وفي كل واحد threadان. تمت مطابقة معرف صورة حاوية التطبيق بين النسختين.
- PostgreSQL 17 وRedis وعمال Celery وNginx منفصلون في مشروع
  `yalla-performance`؛ بيانات وحسابات ووسائط اصطناعية فقط.
- مسار HTTP المستخدم `127.0.0.1:18081`، غير متاح للعامة.
- مولد الحمل يعمل على المضيف نفسه؛ متوسط استهلاكه 7.8% من نواة واحدة،
  وأقصاه 15.6%. لم يصل إلى التشبع وفق معيار الأداة.
- البيانات الأساسية: 100 حساب عميل و20 مندوبًا و1100 منتج، بالإضافة إلى
  سجل طلبات اصطناعي و3000 طلب مسند للمندوبين. المحاكاة النشطة عند حمل 100
  تستخدم 80 حساب عميل و20 حساب مندوب فقط، مع فواصل تفكير 2–5 ثوانٍ.

## الموارد وسلامة البيانات

- متوسط استخدام معالج المضيف أثناء القياس: **72.1%**؛ أقصى عينة **97.9%**.
  ثلاث عينات من أصل 60 تجاوزت 90%. لذلك لا تُستنتج سعة 200 مستخدم أو
  هامش كبير للاندفاعات من نجاح اختبار 100 مستخدم.
- أقصى استخدام ذاكرة المضيف في المرحلة: **17.9%**، مع وجود الإنتاج
  ونسخة الاختبار ومولد الحمل معًا.
- أقصى اتصالات قاعدة الاختبار عبر الحملة: 10؛ عدد deadlocks المسجل: صفر.
- طوابير notifications وmail وdefault وmedia كانت صفرًا في آخر عينة قياس.
- اكتملت بيانات المراقبة، وثبت عدد المستخدمين في عينات القياس، ولم تُسجل
  إعادة تشغيل أو OOM للحاويات في معيار الاستقرار.
- استمرت خدمات الإنتاج بحالتها السليمة أثناء الحملة وبعدها.

تمت مطابقة جميع الكتابات الناجحة عبر **الحملة كاملة، بما فيها الإحماء
والفترات المحيطة بنوافذ القياس**، مع قاعدة البيانات:

عدد مجموعات أحداث الحالة المتكررة للطلب والحالة نفسيهما: **صفر**.
عدد إشعارات الحدث المتكررة للمستلم نفسه: **صفر**.
الفرق بين الاستلام والتسليم ليس فقدًا لتسليم مؤكد؛ توجد رحلات توقفت
عند انتهاء تشغيل المستخدمين، ولم تُحسب كعمليات تسليم ناجحة.

## تحقق الكود وأدوات قابلة لإعادة الاستخدام

نجح 25 اختبارًا موجودًا على PostgreSQL محلي معزول، ثم اختباران جديدان
للتشغيل المختلط ومنع تكرار تحديث المندوب المتزامن. اختبار التشغيل المختلط
المحلي ينفذ 220 استدعاء API داخليًا عبر ثمانية threads؛ وهو اختبار صحة
معاملات منفصل عن اختبار HTTP على السيرفر.

نجح كذلك اختبارا عزل بيانات القياس و17 اختبارًا لأدوات القياس وإيقاف
مولد الحمل، وفحص Ruff والتنسيق للملفات المتأثرة. الإجمالي 46 اختبارًا ناجحًا.
الاختبارات المحلية على نسخة العمل الحالية؛ اختبار الضغط على صورة الإنتاج الحالية.

الملفات المضافة:

- `orders/test_mixed_app_concurrency.py`: صحة التشغيل المختلط وإعادة المحاولة.
- `tools/performance/seed_couriers.py`: بيانات مندوبين اصطناعية مع رفض
  التشغيل خارج إعداد وقاعدة الأداء المعزولين.
- `tools/performance/locust_mixed.py`: خليط دقيق من العملاء والمندوبين،
  مع فحص استجابات API والأسعار ومنع التكرار، وقراءة صفحات القائمة النشطة.
- `tools/performance/run_mixed.py`: حملة تدريجية تحفظ الطلبات والمراقبة
  وتتحقق من صحة الإنتاج وتتوقف عند شروط الحماية.

الأدلة الخام محفوظة على السيرفر في:
`/opt/yalla_backend/tools/performance/artifacts/mixed-20261023/`، خصوصًا
`report.json` وملفات `requests.jsonl` و`resources.jsonl` لكل مرحلة.
لا تحتوي سجلات القياس على أجسام الاستجابات أو بيانات اعتماد الحسابات.

## حدود النتيجة والمتابعة

1. تم قياس مسار القدرة المحلي؛ هذا المسار لا يطبق حد Nginx العام لكل IP.
   الإنتاج يحدد 30 طلبًا/ثانية مع burst قدره 60، و30 اتصالًا متزامنًا لكل IP.
   لذلك لا تثبت نتيجة 429 الصفرية أن 100 مستخدم خلف IP واحد لن تُطبق عليهم
   حدود الإنتاج. لم تُغير هذه السياسة.
2. لم يُقاس TLS أو CDN أو شبكة الهاتف أو واجهة Flutter أو رفع الصور،
   ولم يُختبر اندفاع تسجيل دخول 100 حساب في اللحظة نفسها.
3. عمال Celery الحقيقيون يعملون، لكن لا توجد أجهزة Firebase حقيقية في
   بيانات الاختبار؛ لم يُقاس وصول push أو SMTP الخارجي.
4. الحملة قصيرة وببيانات اصطناعية؛ يلزم اختبار استمرار أطول واندفاعات
   وحجم بيانات مماثل للإنتاج قبل اعتماد سعة أعلى أو توقعات تشغيل أطول.
5. تطبيق العميل يجلب `/orders/my/` كاملًا دون pagination، مع تفاصيل
   وعلاقات وسجل أحداث. هذه نقطة تحسين عند تراكم تاريخ الطلبات؛ لم يتغير
   عقد API أو سلوك التطبيقين في هذه المهمة.

لم تُنشر تغييرات إلى تطبيق الإنتاج. أوقفت خدمات الاختبار بعد اكتمال الحملة،
مع الاحتفاظ ببيانات الاختبار والأدلة؛ لم تُحذف بيانات الإنتاج أو تتغير إعداداته.
