# Production API check — 2026-09-29

The renewed Hostinger deployment responded at `https://api.yallamarket.org`.
`/healthz/` returned HTTP 200 and deployment revision `c3cb3cd0f986` (matching
the repository HEAD). `/readyz/` returned HTTP 200 with database and Redis both
ready. The public login dashboard snapshot also returned HTTP 200. The requests
went through Cloudflare and Nginx to the deployed API.

Read-only GET probes were scheduled below Nginx's 30 requests/second per-IP
limit. `tools/load_smoke.py` now supports `--rate` and `--keep-alive` for this
purpose.

Across 2,000 requests there were no HTTP or transport errors. The final
30-second run sustained 24.73 requests/second on the public snapshot with
p50 88 ms, p95 395 ms, and p99 1234 ms. Connection reuse substantially
improved achieved rate and latency. The earlier high tail latency appeared on
the lightweight liveness endpoint too, so it was not evidence of a specific
Django query bottleneck. These end-to-end timings include the client, network,
Cloudflare, and Nginx; they do not isolate backend processing time.

The Hostinger browser connection was unavailable during this check, so VPS CPU,
memory, database connections, container status, Celery queue, and logs were not
observed directly. No authenticated product/order or write flows were tested
against production. The earlier isolated Docker check in
`docs/LOAD_TEST_2026-09-25.md` covers representative authenticated reads with
seed data, but it is not a VPS benchmark.

This is enough evidence for a gradual, moderate initial launch with monitoring.
It is not a promised concurrent-user ceiling or a test of authenticated and
write flows. The current uncommitted workspace changes are not part of revision
`c3cb3cd0f986` and were not deployed by this check.
