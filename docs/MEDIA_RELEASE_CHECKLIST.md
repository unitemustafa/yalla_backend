# اعتماد إطلاق الميديا

هذه قائمة اعتماد لكل إصدار. تنفيذ الكود لا يساوي اعتماد الإطلاق. النشر إلى الإنتاج خطوة مستقلة بعد توثيق النتائج وتأكيد المسؤول.

## تشغيل بيئة تجريبية مماثلة للإنتاج

- [ ] حفظ نسخة قاعدة البيانات والملفات قبل التغيير؛ `./deploy/backup.sh .env.staging --with-media` على البيئة التجريبية المحددة فقط.
- [ ] بناء صورة السيرفر التي تحتوي FFmpeg/FFprobe، وتطبيق migrations المتوافقة: dashboard 0004 و0005، markets 0014، offers 0013.
- [ ] `docker compose --env-file .env.staging config --quiet`، ثم التحقق من Nginx بـ`nginx -t` داخل الحاوية. تركيب `deploy/nginx/django-proxy.conf` مطلوب.
- [ ] تشغيل `celery-media-worker` على طابور `media` بتزامن 1؛ الإشعارات والبريد تبقى على العامل الحالي. تشغيل beat مطلوب لاستعادة انتظار وسيط متوقف، ومراقبة التعطل، والتنظيف المؤجل.
- [ ] عرض مواصفات الإصدار 1 في الداشبورد؛ التطبيقات القديمة ما زالت تتلقى روابطها الأصلية وحقول التركيز والصورة إضافية.
- [ ] مراجعة حدود Nginx/Django: افتراضي 8MiB، المنتج/الحملة 55، عملية الفيديو 32، ميديا التطبيقات 57، المحل 12. حد 57 يستوعب ثلاثة onboarding وصورة دليفري وposter وفيديو في طلب legacy واحد مع مساحة multipart؛ لا يغير حد أي ملف منفرد.

## الاختبارات الآلية

- [ ] `python manage.py test --settings=config.test_settings`؛ أدوات FFmpeg مطلوبة لاختبارات الفيديو الحقيقي. CI يثبتها ويستخدم PostgreSQL.
- [ ] `python manage.py makemigrations --check --dry-run --settings=config.test_settings` و`python manage.py check --settings=config.test_settings`.
- [ ] فحص Ruff ومخطط OpenAPI؛ تحديث `openapi.yml` بعد أي تعديل API.
- [ ] الداشبورد: lint، TypeScript، اختبارات Vitest، اختبارات Playwright للميديا، وبناء الإنتاج.
- [ ] التطبيقان: `flutter analyze`، واختبارات الصور ومطابقة API والفيديو. اختبارات التحكم تتضمن مهلة 10 ثوانٍ، الخلفية أثناء التهيئة، الإيقاف اليدوي، التنقل، والتخلص من المتحكم.
- [ ] رفع الصور المستطيلة والشفافة وEXIF والصغيرة والتالفة والمضللة، وإثبات عدم قص المنتج والحفاظ على النسبة.
- [ ] MP4 بترميزات متنوعة، رأسي/بلا صوت/تالف/زائد المدة، وملفات 9MiB وقريبة من 30MiB، وخطأ واضح فوق الحد.
- [ ] توقف العامل، تخزين مؤقت متعطل، سقف المحاولات، إلغاء، استبدال أثناء التجهيز، وعدم إرفاق ملف غير جاهز أو فقد الملف السابق.

## الميديا المنشورة

شغّل التقرير على نسخة البيانات التجريبية، دون خيارات إصلاح أو حذف:

```sh
python manage.py audit_media --verify-content --report-json media-audit.json --fail-on-invalid
```

- [ ] مراجعة كل missing/invalid وربطه بالعنصر المعروض؛ أصلح المنشور المخالف بإعادة الرفع والنشر العادي. لا تقص أو تحذف القديم تلقائيًا.
- [ ] مراجعة orphan يدويًا، مع استثناء الملفات الحديثة أو المرتبطة بعملية تجهيز. خيارات الإصلاح القديمة موجودة؛ لا تستخدمها كجزء تلقائي من الإطلاق.
- [ ] التقرير يتحقق من الملفات المخزنة، وليس روابط Cloudinary القديمة؛ يلزم فحص/نقل تلك الروابط إن بقيت في حقول نصية.

## خدمة الميديا واستعادة النسخة الاحتياطية

- [ ] على رابط فيديو جاهز من بيئة الهدف: تشغيل فعلي، `Content-Type: video/mp4`، `Range: bytes=0-1023` يرجع 206 و`Content-Range` صحيحًا، والكاش طويل لاسم UUID الجديد. اختبر المسار عبر CDN/Nginx الحقيقي وليس Django التطويري.
- [ ] رابط صورة الطلب/إثبات التسليم: دون صلاحية يرجع 401/403/404؛ مع حساب مصرح يصل إلى الملف، والكاش `private, no-store`. مسار `/_protected-media/` لا يفتح مباشرة، وأصل عملية التجهيز لا يحصل على رابط عام.
- [ ] تنبيه تجاوز 10 دقائق يظهر، وسجلات `media_job_counts`/`media_job_failed`/`media_job_stalled` تصل إلى نظام المراقبة الفعلي. اضبط إخطار المسؤول في منصة المراقبة المستخدمة قبل اعتماد الإطلاق.
- [ ] جرّب استعادة `postgres.dump` و`media.tar.gz` إلى قاعدة ومجلدات منفصلة على staging؛ تحقق من SHA256 ثم التقرير وروابط الملفات وميديا التطبيقين. في S3 اختبر أيضًا نسخة bucket والسياسة الخاصة؛ النسخ المحلي لا ينسخ bucket.
- [ ] وثّق زمن الاستعادة والنسخة المستخدمة، وتأكد أن عملية الاستعادة لا تشير إلى قاعدة/ملفات الإنتاج.

## حالة التنفيذ المحلي

المتاح هنا: اختبارات ملفات فيديو حقيقية، رفع API حتى التخزين، مواصفات الصور، سلامة التحكم، إعداد Compose، الداشبورد وواجهات API. أجهزة Android/iPhone الفعلية وstaging والإنتاج واستعادة النسخ ليست معتمدة تلقائيًا؛ لا تضع علامة نجاح دون تنفيذها وتوثيقها.

يعتمد المسؤول الإصدار بعد اكتمال جميع البنود، ثم يصرح بالنشر منفصلًا. احتفظ بتقرير الميديا ونتائج الاختبارات والجهازين والاستعادة مع رقم الإصدار.
