# نتائج تنفيذ وتجربة الميديا

التاريخ: 2026-10-02. التغييرات في مساحة العمل؛ لم يتم دفعها أو نشرها للإنتاج. هذا التقرير يسجل الاختبارات المحلية، ولا يمنح اعتماد إطلاق على أجهزة أو خدمات لم تُختبر.

## ما تم تنفيذه

- مواصفات صور من السيرفر بإصدار 1، والتحقق الفني وقواعد كل استخدام في API، ورفع الأصل دون ضغط من الداشبورد. WebP وتصحيح الاتجاه وإزالة البيانات الوصفية على السيرفر.
- أصول الفيديو خاصة، وعامل FFmpeg مستقل بتزامن واحد. تجهيز H.264/AAC، فحص الناتج وfaststart، صورة معاينة، مهلة معالجة، وحالات متابعة وإلغاء وإعادة محاولة. سقف محاولات التخزين محفوظ حتى عند إعادة إرسال الرسالة.
- إرفاق الفيديو الجاهز بصورة ذرية، مع بقاء الميديا المنشورة أثناء التجهيز وحماية من النتائج القديمة. طلب الصور المتعددة يرجع حالة قاعدة البيانات عند فشل التخزين ويحفظ الملف السابق.
- تركيز الغلاف واللوجن ومعاينة 320/390/430/768، وروابط جديدة عند الاستبدال، وتنظيف مؤجل يتحقق من المراجع. حدود الطلبات متطابقة للمسارات المقابلة في v1 وv2.
- عرض فيديو بمهلة تهيئة 10 ثوانٍ، وصورة بديلة، وإيقاف في الخلفية وعند التنقل، واحترام الإيقاف اليدوي. فيديو الحملة الرأسي يظهر كاملًا؛ الفيديو الفاشل لا يترك مؤشر تحميل مستمرًا.
- تقرير تدقيق تقني للميديا، ومؤشرات الطابور وتنبيه تجاوز 10 دقائق، ودليل رفع واحد وقائمة اعتماد لكل إصدار.

## نتائج التحقق المحلي

| الفحص | النتيجة |
|---|---|
| Django، كامل الاختبارات بعد تصحيح النشر المتعدد | 762 اختبارًا ناجحًا، دون اختبارات متجاوزة في نتيجة التشغيل |
| تغطية السيرفر بالأمر المستخدم في CI | 90% كما يعرض coverage؛ اجتاز `--fail-under=90` |
| صور مستطيلة/شفافة/EXIF/صغيرة/تالفة/امتداد مضلل | ناجح؛ نسبة الأصل محفوظة وعدم قص المنتج مثبت |
| ملفات MP4 حقيقية، ترميز MPEG-4/H.264، دوران، رأسي، صوت/بلا صوت، مدة وتلف وfaststart | ناجح |
| رفع API بحجم 9MiB و29MiB وما فوق 30MiB | ناجح؛ الملفات الكبيرة MP4 صالح مع padding، للتحقق من مسار الرفع وحدوده |
| فشل التخزين والمحاولات الجديدة والإلغاء والاستبدال والنشر غير الجاهز | ناجح؛ اختبارات الانحدار موجودة |
| الطلبات وحدود Nginx بعد توحيد v2 | 8 اختبارات ناجحة؛ فحص القالب لا يعادل تشغيل Nginx |
| Django check وغياب migrations مفقودة وRuff وOpenAPI | ناجح |
| Bandit بنفس مستوى CI العالي | اجتاز؛ لا نتائج Medium/High، وتوجد نتائج Low مستبعدة بحسب إعداد CI |
| الداشبورد Vitest | 51 ملفًا، 265 اختبارًا ناجحًا |
| الداشبورد Playwright | 3 اختبارات ناجحة: بقاء الفيديو القديم، معاينات القص ورفع الأصل، وإلغاء الفيديو عند تغيير نوع ميديا الحملة |
| TypeScript وsizecheck وبناء إنتاج Next.js | ناجح |
| ESLint على الداشبورد كله | اجتاز دون أخطاء؛ تحذير سابق عن `previewPayload` في نموذج إنشاء الطلب |
| تطبيق العميل | analyze كامل ناجح؛ 22 اختبارًا للميديا و8 للحملات ناجحة، وإعادة اختبار الفيديو الستة بعد ربط مراقب التنقل ناجحة |
| تطبيق الدليفيري | analyze كامل ناجح، و6 اختبارات لصور اللوجن/البدائل/التركيز والنتائج المعرّفة ناجحة |
| Compose config | صالح باستخدام قيم تجريبية؛ لم تُشغّل الحاويات |

اختبارات Playwright تعزل HTTP ببيانات محاكاة؛ لا تثبت خدمة Nginx أو تشغيل الفيديو على الهاتف. اختبارات السيرفر تجهز ملفات فيديو فعلية على التخزين المحلي. تجربة الأقفال والتخزين الحقيقي على PostgreSQL/S3 وعامل Celery الفعلي تبقى ضمن staging.

فحص `deadcode` في الداشبورد لم يجتز بسبب ثلاثة exports موجودة قبل هذه التغييرات: `numericValue` في `order-review/domain.ts`، و`compareItemText` و`matchesItemSearch` في `products/list/domain.ts`. لذلك لا يُعتبر الأمر الشامل `npm run check` مجتازًا بالكامل؛ الفحوص الناجحة أعلاه شُغّلت منفصلة. لم تُعدّل تلك الأجزاء غير المتعلقة بالميديا.

## اعتماد الإطلاق المتبقي

1. بناء وتشغيل الحاويات على staging ونجاح `nginx -t`، وتطبيق migrations وتشغيل طابور media وbeat. محرك Docker غير متاح في هذه الجلسة.
2. تشغيل CI على PostgreSQL، وتجربة العامل والتخزين وتعطل الخدمات، وربط السجلات بإخطار المسؤول في منصة المراقبة الفعلية.
3. تشغيل `audit_media --verify-content` على البيانات المنشورة ومراجعة كل ملف مخالف أو رابط Cloudinary قديم؛ لم تُراجع بيانات الإنتاج هنا.
4. اعتماد نسخة Release على Android وiPhone فعليين تحت الشبكة الضعيفة والانقطاع والخلفية والتنقل، والتأكد من القص.
5. اختبار رابط بيئة الهدف: التشغيل وRange/206 وContent-Type والكاش وصلاحيات الصور الخاصة، ثم استعادة نسخة قاعدة البيانات والملفات في مكان منفصل.
6. اعتماد النتائج، ثم تنفيذ النشر كخطوة مستقلة.
